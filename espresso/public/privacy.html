A little transparency

Privacy Policy

Initial version · October 18, 2026

This policy describes the current implementation. Before public hosting, the operator should finalize host-specific logging, backup retention, and any additional disclosures.

Who runs this project

Espresso Bot is operated by Harper. Contact the operator using the contact details at harperurias.com for privacy questions or deletion requests.

Information used for moderation

The bot reads message text in accessible server channels while it is online to check the server's configured rules. Up to 1,000 recent message objects may be held in process memory; their content is not written to the moderation database. Attachment contents, images, and audio are not scanned.

SQLite stores server settings, server/user/moderator IDs, warning timestamps and reasons, message or interaction identifiers used to avoid duplicate warnings, and panel configuration audit records identifying the actor, changed field names, and time. Automatic warning reasons contain a rule name, not the original message. Staff may include personal information in manual warning reasons.

Public website statistics

The home page displays an aggregate count of servers in the connected bot's current cache, its connection status, and Discord gateway heartbeat latency. These figures refresh every 30 seconds while the page is visible. The public statistics endpoint does not publish server names, server or member IDs, message contents, or credentials.

Optional identity-based abuse filters use small English word and phrase rules selected by server administrators. No identity, personal belief, or author intent is inferred. Category/level names, rather than original offensive messages, are stored as automatic warning reasons.

Reaction-role configuration stores message, channel, role, and emoji mappings. When Espresso grants a role, it records the server ID, member ID, role ID, and mapping key so a later reaction removal can revoke only a recorded grant. Removing a mapping or a server clears the associated ownership records, but does not automatically remove roles from Discord members.

Member screening and website activity

Optional member screening uses Discord account creation and server join times, member/server IDs, and the configured rules to determine whether staff review is required. SQLite stores screening status, agreement time and rules hash, decision/audit times, reviewer IDs, and the access role ID. Existing roles are not removed by screening. These records are visible to authorized server staff.

The private website activity log stores action titles, categories, metadata, and times for moderation, settings changes, reaction roles, and verification. Original message bodies, manual warning reasons, and credentials are not included. New website log entries are limited to 30 days and 10,000 per server, with expired entries hidden on reads and pruned at startup and new writes. Screening cases and decision audit records remain until the server data is removed or the operator handles a deletion request; they do not share the activity log expiry. Backups require separate retention practices.

Role-template post records store the requesting moderator ID, a hash of the reviewed choices, channel and message IDs, newly created role IDs, and the posting outcome. These records prevent duplicate posts and remain until server data is removed. The panel keeps an unconfirmed template draft in this browser tab’s session storage so you can check or retry the same request after a lost connection; it contains template choices and no credentials. Closing the tab clears that draft. Optional identity labels are self-selected roles visible according to your Discord server’s settings; Espresso does not infer identities.

Reports, appeals, cases, and community tools

Private reports and appeals store the submitted explanation, reporter and target IDs, a Discord message link when provided, an optional case reference, assignment, status, resolution, review notes, and audit timestamps. Reported message bodies are not copied automatically. Staff with Moderate Members can read these through private commands and the limited website staff desk. Manage Server is required for configuration, schedules, settings history, health details, and role-menu management. Members can view only their own moderation cases through /mycases and their own report/appeal statuses and member-facing responses through /myreports. Optional outcome DMs contain only the final status and separate member-facing text, never internal staff notes; delivery status is recorded. Review notes are kept in the private staff desk, not channel or process logs.

Moderation cases record the action type, actor and target, reason, outcome, and time. Removing a warning or clearing warning rows retains case and removal audit records. Optional warning expiry stops a warning counting toward escalation without deleting its history. Temporary raid recovery stores channel IDs, the permission or slowmode values Espresso changed, and restoration times. Coordinated-repeat detection uses bounded text hashes and member/timestamp buckets in memory rather than saving original messages to SQLite.

Scheduled announcements and reminders store the message text, author and channel IDs, schedule and repeat settings, notification choice, and delivery outcome. Welcome cards and coffee cards can display a Discord avatar. Daily prompts retain their latest queued date. Community polls use Discord's native poll feature; Espresso does not maintain a separate vote database. These features are optional per server, and message mentions are suppressed except an explicitly enabled notification-role ping.

Reports, appeals, review notes, moderation cases, warning-removal records, scheduled posts, and community state remain until server data is removed or the operator handles a deletion request. They do not share the Activity log's 30-day expiry. Receiving a server-removal event clears these database records too. Previously sent Discord messages and backups require separate deletion handling.

Settings history and role menus

Versioned settings history stores complete server configuration snapshots, changed fields, actor IDs when available, and times. Only server managers can inspect or restore them. Named-timezone schedules store recurrence rules, weekdays, local clock time, edit versions, and delivery/recovery status. Role menus store their server, author, channel and message IDs, menu labels/descriptions, selected roles, selection limits, status, and request identifiers; ownership records track roles granted by a menu to a member. Coffee-card designs and custom prompt libraries are saved with server settings.

The private overview uses aggregate warning-rule counts and workflow metadata such as waiting times and delivery failures. It does not create a separate message-content analytics database. Each dashboard section checks the current permissions needed for its data. These snapshots, configurations, report responses, and menu ownership records follow server cleanup and operator deletion practices; clearing warnings or letting them expire does not delete these separate records.

Discord sign-in and cookies

Sign-in requests Discord's identify and guilds permissions to identify you, list your servers, and verify management access. The Add Espresso flow also requests the bot installation and application-command scopes, so you can install and sign in in one authorization. It installs only after you approve a server in Discord. Your Discord user ID and display name, OAuth access token, and session protection tokens stay in server memory for the session. Refresh tokens are not retained. OAuth/session credentials are not sent to the browser beyond opaque session cookies and a request-protection token.

The website uses necessary, HttpOnly cookies for a sign-in attempt (up to five minutes) and a session (up to eight hours, or the access token's earlier expiry). Restarting the process ends sessions. Logout removes the active local session. Authorization granted to the application in Discord remains until you revoke it there.

Temporary in-memory rate-limit entries use the connection peer address and recent sign-in times to limit repeated login attempts. These entries are not written to the application database. A hosting proxy may supply the peer address instead of your device address.

Why information is used and who sees it

Information is used to enforce configured rules, provide staff warning history, apply timeouts, authorize settings access, prevent duplicate actions, and diagnose failures. Authorized staff can view warning reasons through private Discord command responses; warning notices may also be sent to the affected member by DM. Timeout reasons may appear in Discord's audit log.

Action metadata and outcomes may be sent to a configured Discord staff channel and the hosting process log. The application does not include message bodies or manual warning reasons in those logs. Access to staff channels is controlled by each server. The operator can access the database and host logs.

Retention and deletion

Warning rows and server settings remain until cleared or removed. Optional warning expiry affects escalation eligibility rather than data retention. Moderation case and removal audit history is retained when warning rows are cleared. Authorized staff can use /mod clearwarnings to delete a member's warning rows; associated moderation case and removal audit records remain. When the running bot receives a server-removal event, it deletes that server's settings, warnings, versions, panel configuration audit records, reaction-role ownership and template-post records, screening cases and decisions, and website activity logs. If it is offline at removal, operator cleanup is required.

To request access, correction, or deletion of your information, contact Harper with your Discord user ID and relevant server ID. The operator may verify ownership or authority before handling the request. Do not send credentials. Removal from the local database does not automatically remove Discord messages, audit logs, or copies in host backups. Backup and infrastructure log retention must be finalized before public launch.

Optional Community hub features

Server managers can enable private support tickets, native events, suggestion voting, personal voice rooms, saved replies, birthday greetings, message highlights, and café profiles. The bot stores server-scoped settings and operation records, including room/message IDs, ticket subjects and close reasons, suggestions and votes, event metadata and reminder subscriptions, voice room ownership, delivery outcomes, saved replies, and temporary role ownership. Hub configuration requires current Manage Server access. Ticket transcripts are excluded from dashboard list responses.

Text transcripts require both server permission and an explicit request when the member opens the ticket. They include up to 1,000 recent messages and attachment links, without downloading media. Authors and the current support team can privately download them. Closed ticket content and transcripts expire after 30 days. Attachment links may expire separately. Discord administrators retain their normal room access; staff may retain downloaded copies.

Members opt into birthday greetings by saving only a month and day, into event reminders through a subscription command, and into public café profiles by creating a card. Birthday dates are not listed on the dashboard or café profile. Profiles contain a chosen bio/theme, public thanks total, and staff-awarded badges. Privacy commands remove birthdays, unsubscribe reminders, or delete a profile and its visible award history. A separate award-limit ledger expires after 24 hours and prevents deleting a profile to reset award limits.

Highlights copy bounded text excerpts and links from approved public channels, excluding private threads and bot/webhook messages. Members can opt out per server; staff can remove highlights. Source deletion or loss of public visibility queues removal. An outage or permission change can delay deletion. Opt-outs persist until changed or server cleanup. Attachment media is not copied into the board or the local database.

These records are deleted with the server’s other local data when the running bot receives its removal event. Disabling a feature does not erase its history. Removing local records does not delete previously sent Discord messages, downloaded transcripts, audit logs, or backups. The operator can assist with access and deletion requests.

Other services

Discord handles account authorization and bot communications under its Privacy Policy. The pages request Playfair Display and Plus Jakarta Sans from Google Fonts; those requests transmit normal connection information such as IP address to Google. This app includes no advertising, analytics trackers, or sale of user data. A future hosting provider may process connection metadata; the operator must update this policy to identify relevant hosting practices before launch.

Changes

Changes to data handling should be reflected here before the corresponding feature is made public. This project is unofficial and is not affiliated with Discord or Sabrina Carpenter.
